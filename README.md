# Flow
# Flow 需求文档（PRD）v0.1

> 产品名：**Flow**  
> 目标平台：**Android（优先）**，iOS（可选）  
> 前端：**React Native**（你说的 “reactive native” 我这里按 React Native 理解）  
> 后端：**FastAPI（可选：仅当需要在线音乐列表/在线播放）**  
> 定位：**“用音乐替代闹钟”的定时播放 + 基础音乐播放器**

---

## 1. 背景与目标

### 1.1 背景
你想做一个能**每天定时播放音乐**的 App，达到“取代闹钟”的效果；同时借此完整实操一遍“从 0 到 APK”以及（可选）“前后端联动”开发流程。

### 1.2 产品目标（Goals）
1. 用户可以设置每日定时播放（像闹钟一样可靠）。
2. 音乐来源支持两种模式：
   - **本地模式（单机 App）**：扫描手机本地音乐并播放。
   - **在线模式（带后端）**：从服务器获取音乐列表并在线播放。
3. 提供常见播放器能力：播放/暂停、上一首/下一首、进度条、列表、删除、拖动排序。
4. 输出可安装的 **Android APK**（Debug/Release）。

### 1.3 非目标（Non-goals）
- 不做复杂社交、评论、分享、推荐算法。
- 不做 DRM/付费音乐版权分发（仅支持用户自有/授权资源）。
- v0.1 不追求多设备同步与账号体系（后续可扩展）。

---

## 2. 用户与使用场景

### 2.1 目标用户
- 想用音乐唤醒自己、替代系统闹钟的人。
- 想要简单播放器 + 定时功能，不追求“重度音乐社区”。

### 2.2 典型场景
1. **每日 7:30** 自动播放“起床歌单”，手机锁屏也能正常响起。
2. 用户有一堆本地 MP3，想一键扫描导入并整理顺序。
3. 用户有自己的服务器音乐库，点击“获取音乐”后展示列表并在线播放。

---

## 3. 术语与约束

- **定时播放**：按用户设置的时间点触发播放（每天/指定星期几）。
- **唤醒模式**：触发后应尽量确保能发声（需要处理权限、后台限制、通知/前台服务）。
- **本地音乐**：通过 Android MediaStore 或文件选择器读取的音频资源。
- **在线音乐**：后端返回可播放 URL（如 MP3、AAC、HLS）。

---

## 4. 需求范围与版本规划

### 4.1 MVP（v0.1 必做）
- ✅ 本地扫描/导入音乐（至少能导入系统媒体库里的音频）
- ✅ 播放器：播放/暂停、上一首/下一首、进度条、当前播放信息
- ✅ 播放列表：展示、拖动排序、删除
- ✅ 定时播放：每日固定时间触发（至少 1 组定时）
- ✅ Android 打包：Debug APK + Release APK（带签名）

### 4.2 v0.2（增强）
- 在线音乐：从服务器拉取列表、在线播放、切换音质（可选）
- 多组定时（例如工作日/周末不同）
- 逐渐增大音量（fade-in）、自动停止（例如播放 30 分钟后停止）

### 4.3 v1.0（可选方向）
- 下载离线缓存、收藏/最近播放
- 账号体系 + 多端同步（后端升级）
- 更完整的播放器体验（歌词、均衡器等）

## 5. 功能需求（详细）

### 5.1 音乐来源管理

#### 5.1.1 本地音乐（单机）
**用户故事：**  
作为用户，我想从手机里找到音乐并导入到 Flow，这样我可以在 App 里直接播放和定时播放。

**功能点：**
- 扫描系统媒体库（推荐 Android MediaStore），列出可用音频：
  - 字段：标题、艺术家、时长、文件大小（可选）、uri/path
- 支持“手动添加”：
  - 通过系统文件选择器选取音频文件（Storage Access Framework）
- 将导入的音乐保存为“Flow 播放列表”本地数据（SQLite/AsyncStorage）。

**验收标准：**
- 首次打开可请求读取媒体权限并成功展示音乐。
- 至少能导入并播放 3 种常见格式（MP3/AAC/M4A 视设备支持）。

#### 5.1.2 在线音乐（可选：有后端）
**用户故事：**  
作为用户，我想点击“获取音乐”从服务器拿到音乐列表并在线播放。

**功能点：**
- App 端：
  - 点击按钮请求后端 `/api/tracks`
  - 展示返回的音乐列表并可点击播放
- 服务端：
  - 返回 track 列表（含可直接播放的 URL）
  - 支持简单分页/搜索（可选）

**验收标准：**
- 点击获取后 3 秒内展示列表（局域网/普通服务器视情况）。
- 选择任意 track 可以播放且可以上一首/下一首切换。

---

### 5.2 播放器核心

#### 5.2.1 播放控制
- 播放/暂停
- 上一首/下一首
- Seek（拖动进度条）
- 显示：封面（可选）、标题、艺术家、已播放/总时长

#### 5.2.2 播放队列/列表
- 列表展示（当前队列）
- 拖动排序（改变播放顺序）
- 从列表删除
- 播放模式（MVP 可先只做顺序播放；循环/随机可放 v0.2）

**验收标准：**
- 拖动排序后，下一首按新顺序播放。
- 删除当前播放曲目时，自动播放下一首或暂停（规则见 9.1）。

---

### 5.3 定时播放（“替代闹钟”）

#### 5.3.1 定时规则（MVP）
- 支持 1 组定时：
  - 时间：HH:mm
  - 重复：每日（每天触发）
  - 动作：触发时开始播放指定播放列表（或继续播放队列第一首）

#### 5.3.2 触发行为
- 到点后：
  1. 唤起音频播放（必要时启用 Android 前台服务 + 通知）
  2. 开始播放（若无曲目则提示失败原因）
  3. 展示“正在唤醒”通知，点击通知进入播放页

#### 5.3.3 权限与后台限制（Android 关键）
- 需要考虑：
  - 通知权限（Android 13+）
  - 前台服务（Foreground Service）与媒体播放通知
  - 设备省电策略可能导致定时不准：需要在设置页提示用户允许后台运行/忽略电池优化（可选但建议做提示）

**验收标准：**
- 屏幕锁定情况下，到点能播放（在常见机型/系统限制下尽量稳定）。
- App 杀进程后（被系统回收），仍能在多数情况下按时触发（取决于实现策略）。

## 6. 页面与交互（UX）

### 6.1 页面结构（建议）
1. **首页 / 播放页**
   - 当前播放信息
   - 播放/暂停、上一首/下一首
   - 进度条
   - “播放列表”入口
2. **播放列表页**
   - 列表（拖动排序、左滑删除或按钮删除）

   - “获取服务器音乐”按钮（在线模式）
3. **定时设置页**
   - 开关：启用/禁用
   - 时间选择器
   - （v0.2）重复规则、播放时长、fade-in
4. **设置/关于**
   - 后端地址（在线模式）
   - 权限状态提示（通知、电池优化等）
   - 版本号

## 7. 数据模型（建议）

### 7.1 Track（曲目）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 本地生成 UUID 或服务端 ID |
| title | string | 标题 |
| artist | string | 艺术家（可空） |
| durationMs | number | 时长毫秒（可空） |
| sourceType | enum | `local` / `remote` |
| uri | string | 本地 content:// uri 或远程 URL |
| artworkUri | string? | 封面（可选） |

### 7.2 Playlist（播放列表/队列）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | UUID |
| name | string | 默认 “Flow 列表” |
| trackIds | string[] | 按顺序存储 |

### 7.3 AlarmSchedule（定时配置）
| 字段 | 类型 | 说明 |
|---|---|---|
| enabled | boolean | 是否启用 |
| timeHHmm | string | 例如 “07:30” |
| repeat | enum | MVP：`daily` |
| playlistId | string? | 不填则使用当前队列 |

## 8. 后端（FastAPI）需求（在线模式时启用）

### 8.1 接口设计（MVP）
- `GET /api/health`
  - 返回：`{ "ok": true }`
- `GET /api/tracks`
  - 返回：`[{ id, title, artist, durationMs, url, artworkUrl? }]`

### 8.2 服务端资源组织（建议）
- 方案 A（简单）：服务器目录下存音频文件，后端扫描目录生成列表。
- 方案 B（规范）：写入 SQLite/Postgres 的 tracks 表，支持搜索/标签。

### 8.3 安全与限制（MVP 简化）
- 可先不做鉴权（局域网/个人服务器）。
- 若公网提供，建议 v0.2 加简单 token 或 basic auth。

---

## 9. 业务规则与边界情况

### 9.1 删除曲目规则
- 删除非当前播放曲目：从列表移除即可。
- 删除当前播放曲目：
  - 若列表仍有下一首：自动播放下一首
  - 否则：停止播放并显示“列表为空”

### 9.2 定时触发但无可播放曲目
- 行为：弹通知提示 “Flow 定时触发失败：无曲目”，并记录日志（本地）。

### 9.3 在线播放失败
- 网络错误：提示“网络不可用”，可重试。
- 403/404：提示“资源不可用”，自动跳到下一首（可选）。

## 10. 技术架构建议（实现导向）

### 10.1 React Native 侧（建议库）
- 播放：`react-native-track-player`（常见选择）
- 列表拖拽：`react-native-draggable-flatlist`
- 本地存储：`@react-native-async-storage/async-storage`（MVP），或 SQLite（更稳）
- 后台/定时：
  - Android 定时较复杂：可选 `react-native-alarm-manager` / `react-native-background-fetch` / 自写原生模块 + `AlarmManager/WorkManager`
  - **建议路线**：MVP 先用 WorkManager/AlarmManager（原生）做可靠触发，再桥接到 RN 调起 TrackPlayer

> 备注：Android 对后台与定时限制较多，想“像闹钟一样”稳定，最终大概率需要 **原生（Kotlin/Java）参与**，RN 主要做 UI 与业务层。

### 10.2 FastAPI 侧
- 提供曲目列表与静态文件服务（或反向代理到对象存储）。
- Nginx（可选）做静态文件分发更高效。

## 11. Android 打包 APK 流程（你要重点实操的）

### 11.1 开发环境（必备）
- Node.js + npm/yarn
- Java JDK（通常 17）
- Android Studio + Android SDK
- React Native CLI 环境

### 11.2 Debug APK（最先跑通）
1. 初始化 RN 项目
2. `npx react-native run-android`
3. 生成 Debug APK（通常在 `android/app/build/outputs/apk/debug/`）

### 11.3 Release APK（签名版）
1. 生成 keystore（一次性，妥善保存）
2. 在 `android/gradle.properties` 或 `android/app/build.gradle` 配置 signingConfig
3. 执行 `./gradlew assembleRelease`
4. 输出路径：`android/app/build/outputs/apk/release/`

### 11.4 关键注意点
- Release 需要正确的包名、版本号（versionCode/versionName）
- Android 13+ 通知权限可能影响“到点提示/播放通知”
- 后台/定时相关需要在 Manifest 配置权限与 Service

- 至少测试 2 个 Android 版本（例如 Android 10/13+）
